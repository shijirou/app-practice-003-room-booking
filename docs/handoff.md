- `CLAUDE.md` の「報告と判断の誠実さ」5 項目を、報告のたびに守る。
- 「おすすめ」など任せる選択肢を出すときは、「学習のため、選んだ理由も一言書いてください」を添える。
- ポートフォリオ（文章・写真）を直したら、GitHub の表示を見てプロの視点で添削する。分かりやすさを最優先にする。
- 画面を作る前は、`docs/screen-design.md` の「要素の一覧」と最終モックを全部読み、入れる・入れない要素の了承を取る。
- 画面の見た目や写真は、ユーザーに確認してもらってから、コミットして PR にする。
- 表示や文言を変える PR は、`e2e` も `grep` し、手元で `npm run e2e` を実行してから出す。
- ブランチを作るコマンドと commit のコマンドは分ける。`push` と `main` を同じコマンドに入れない。
- CI が赤いときは、まずログの原因を読む。寸法のテストは、手元（Windows）と CI（Linux）で結果が違うことがある。
- ファイルの編集は Edit ツールか Node で行う（CRLF に注意）。`git checkout -- .` などの、作業を捨てるコマンドは打たない。
- 調査だけの回は、コードもファイルも変えない。やり取りの文章で絵文字を使わない。
