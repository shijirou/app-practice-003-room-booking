## まちがい（要件・設計書とのずれ）
| 場所 | 内容 | なぜ問題か | どうしたか |
|---|---|---|---|
| API のエラーの形 | 必須の値が足りない（`/api/reservation-days` に from なし）・宛先がない 404・できない操作 405・JSON 以外 415 は、`{"timestamp":…,"status":…}` の形で返っていた。想定外の 500 も同じ | 設計書に「どの API も、失敗は同じ形で返す」「500 は `{"message": "エラーが起きました"}`」とある | `{"message": "..."}` にそろえた。想定外はログにだけ詳細を残し、返事には出さない。テスト追加（`ErrorFormatTest`・`ApiExceptionHandlerTest`） |
| README の「起動方法」「使い方」 | 「（あとで書く）」のままだった | 公開リポジトリの入口で、使い方が分からない | 起動の順番と、画面の使い方を書いた |
| 要件定義書の「安全性（入力）」 | 「API は画面の宛先（5173）だけを CORS で許可する」とあるが、実装に CORS の設定は無い | 書いてあることと実装が違う | 実際は、画面が Vite の中継（`/api` → 8080）で同じ場所から呼ぶので許可が要らない（ほかの場所からは拒否される。`Origin` を付けて確かめた）。文書のほうを直した |
| キーボードだけでの操作 | 空き枠（新規予約の入口）がマウス専用で、キーボードでは新しい予約を作れない | 要件定義書の「キーボードだけでも操作できる」とずれている。（予約の確認・変更・キャンセルは、下の一覧のボタンからキーボードでできる） | **直した（2026-11-23・#122）**。［＋ 予約する］ボタンを足し、キーボードだけで予約まで進めるようにした。テスト 9 件追加 |
